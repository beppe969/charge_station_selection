\section*{Reproduce the revised manuscript}
Start in the directory containing this guide. The city policy comparisons, Washington planning experiments and manuscript inputs use Python. The accompanying requirements file records the tested versions. With a Python 3.9 environment, run
\begin{lstlisting}
python -m pip install -r requirements.txt
python run_revised.py
\end{lstlisting}
The runner verifies the station-file checksums and uses the archived MATLAB timings by default. Pass \texttt{--matlab} followed by the executable path to regenerate timings on the local machine. Keep \texttt{data/}, \texttt{code/} and \texttt{results/} in this directory.

\subsection*{City comparisons}
\texttt{code/revised\_primary\_cities.py} constructs the primary, half-load comparison on the source-reconciled public inventory for each city. It rebuilds the footprint and sets the request count to half the retained port count, rounded up. Thirty seeded layouts per city share the same requests and operating conditions across policies. Every initial request enters the service denominator. Comparisons on a fixed served group hold vehicle identities constant. Generalized monetary cost includes travel, the energy bill and valued time. The nominal class proxies are 1.4, 7.2 and 50~kW for Level~1, Level~2 and DC fast, subject to vehicle power acceptance.

\begin{lstlisting}
python code/access_audit.py
python code/revised_primary_cities.py
python code/revised_city_study.py
python code/revised_public_access.py
python code/revised_scarcity.py
\end{lstlisting}
\begin{itemize}
\item Files in \texttt{results/} with the prefix \texttt{primary\_city\_} contain inventory counts (\texttt{inventory.csv}), observations (\texttt{layouts.csv}), summaries (\texttt{summary.csv}) and contrasts (\texttt{factorial.csv}).
\item \texttt{revised\_city\_study.py} generates the original all-listed half-load comparison and the Washington load and assumption sensitivities. Outputs include \texttt{city\_layouts.csv}, \texttt{city\_summary.csv} and \texttt{city\_factorial.csv}. The factorial contrasts include hypothetical fallback costs of \$50, \$100 and \$200 per unserved request.
\item \texttt{revised\_public\_access.py} keeps the original all-listed demand and site attributes fixed while restricting available ports. Chicago includes a third arm capping public counts at source multiplicity. Outputs are \texttt{access\_layouts.csv} and \texttt{access\_summary.csv}.
\item \texttt{revised\_scarcity.py} prices the opportunity cost of consuming Washington ports using a separate forecast sample. It compares the resulting online policy with sequential and batch cost policies at half and high load. The observations, summaries and paired contrasts have the prefix \texttt{scarcity\_}.
\end{itemize}

\section*{Washington feasibility and investment scenarios}
\texttt{code/planning\_study.py} diagnoses failed layouts with maximum matching and alternating paths. It freezes inputs within each range and budget sweep, selects an expansion site on 32 discovery layouts and estimates its effect on 96 independent evaluation layouts. Sixty-four further layouts supply the sweeps and thresholds.
\texttt{results/planning/} contains the feasibility frontier, thresholds, deficient group and intervention outcomes. Run \texttt{code/planning\_routes.py} next to retest the selected sites on the same 96 layouts with street distances. Its two CSV outputs have the prefix \texttt{route\_intervention}.

\subsection*{Street-network sensitivity}
\texttt{code/road\_study.py} compares planar and directed street distances on the same 30 Washington half-load layouts, site attributes and arrival orders. The offline input \texttt{data/dc\_road\_blocks.csv.gz} contains 13,833 blocks from the District Department of Transportation's \href{https://catalog.data.gov/dataset/roadway-block}{Roadway Block layer}, retrieved November 22, 2026. The graph uses the reported lengths in metres and permits travel forward for OB, in reverse for IB and in both directions for BD. It omits 232 blocks with unknown direction.

Endpoints rounded to five decimal degrees define graph nodes. EVs and sites connect to their nearest node by straight access legs. A pair with no directed path is ineligible. A third arm limits snapping to the 8,505 endpoints in the largest strongly connected component of the 8,638-node graph, testing how attachment to disconnected streets affects service. Routing represents street geometry and direction, without turn restrictions or time-varying traffic.
The road results appear in \texttt{results/roads/}. Three CSV files give layout observations, summaries and paired contrasts. The file \texttt{network.json} records the graph metadata. To retrieve a fresh ArcGIS extract, run \texttt{prepare\_dc\_roads.py} in \texttt{data\_preparation/}.

\section*{Verify model and solver implementations}
The reference run used MATLAB R2020a with Optimization Toolbox 8.5.
\begin{lstlisting}
addpath('code');
verify_assignment;
\end{lstlisting}
\texttt{code/verify\_assignment.m} checks the original integer program with one aggregate budget row per EV against a filtered LP and minimum-cost matching. A one-EV example returns 11 for the original integer program and filtered LP, and 7 for the original budget-row LP. Twelve feasible seeded rectangular or square instances check equivalence. Additional cases exercise tied optima, partial service, missing edges and costs above one million.

The benchmark uses two fleet sizes, three edge probabilities and five realizations per setting. A planted matching ensures full service. All four implementations receive identical eligible edges and costs in each realization and run in shuffled order. The sparse-input and dense-input paths pass the same normalized edge costs and cardinality reward to MATLAB's \texttt{matchpairs}. The LP and MILP instantiate one variable per acceptable pair. The reduced LP has integral vertices. The test uses dual simplex.
\begin{itemize}
\item \texttt{results/solver/benchmark\_trials.csv} records edge counts, setup, solve and end-to-end times, primary input matrix sizes, objectives and integrality residuals. Shared inputs and solver workspace are excluded from matrix storage.
\item \texttt{benchmark\_summary.csv} gives group medians and timing ranges. \texttt{environment.txt} identifies the MATLAB environment and seed.
\end{itemize}

\section*{Station inventories and geocoding}
The package includes the national address and connector-count extract \texttt{data/USA\_EV\_CS.csv}, attributed in the original package to the U.S. Department of Energy. The agency maintains the \href{https://afdc.energy.gov/stations}{Alternative Fueling Station Locator}. The historical extraction date and original geocoding decisions are unavailable. The three shipped city files supply geocoded records. Four Chicago records lack usable coordinates. The Washington file includes 333 Washington labels and one Alexandria label. The Manhattan file uses the city label New York.

\texttt{code/access\_audit.py} joins each usable city-file record to the national extract by normalized street, city, state, five-digit ZIP and the three port-class counts. All matched groups have a single access classification. The primary analyses keep public groups and cap each group's row count at its multiplicity in the national extract. Records at identical coordinates then contribute their retained ports to the same site. The row-by-row crosswalk \texttt{results/inventory\_access.csv} records candidate national row numbers, access classification and whether the geocoded row is within that source count.

\subsection*{Prepare a fresh selection}
\texttt{data\_preparation/Coordinates\_Finder.m} selects public records with positive port counts via \texttt{process\_EV\_charging\_data} and queries OpenCage with the operator's \texttt{OPENCAGE\_API\_KEY} environment variable. Give the state, source city label(s) and a new output filename. New York is the default city for NY. An empty city string selects all eligible records for the state.
\begin{lstlisting}
addpath('data_preparation')
Coordinates_Finder('NY', "New York", 'manhattan-new-geocodes.csv');
\end{lstlisting}
\texttt{merge\_census\_results} imports a separate U.S. Census batch geocoder response by row ID. Use a working spreadsheet copy for that merge and \texttt{clean\_city\_file}, which update their input spreadsheet. New geocodes produce a different dataset.

\subsection*{Historical MATLAB explorations}
From \texttt{code/}, \texttt{run\_all\_simulations(false)} runs the updated historical explorations. With \texttt{true} it first reruns the synthetic preference sweep. The shipped synthetic knee gives 3.175 dollars/km and 0.287 dollars/min. Revised city valuations are specified directly in Python. Historical scripts use Optimization Toolbox and Statistics and Machine Learning Toolbox. The legacy timing script can additionally measure CVX/MOSEK. Earlier plots in \texttt{figures/} document pre-revision results. The original package identifies its code license as MIT. Contact \href{mailto:luca.ambrosino@polito.it}{Luca Ambrosino} about inventory provenance.

The historical entry point \texttt{hungarian\_assignment\_sparse} selects dense-input MATLAB matching for compatibility. Use \texttt{matchpairs\_assignment(A,C,'sparse')} for the sparse input. The index of an unmatched vehicle's port is zero. A Boolean output reports whether every vehicle was served.
